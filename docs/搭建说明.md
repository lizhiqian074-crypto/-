## 第五部分：资源导入

### 模型

1. 复制 GLB 到默认目录，或修改 JSON 的 `deer_model` / `forest_model`。GLTF、FBX、OBJ 也可读，推荐 GLB；OBJ 没有骨骼动画。
2. 等 Godot 完成 Import。FBX 建议 Godot 4.3+；BLEND 需 Blender，当前工具不自动处理。
3. 游戏运行时森林自动实例化到 EnvironmentRoot，鹿自动实例化到各自 Visual。**不要再将同一模型拖到 Visual，否则会重复显示两份。**
4. 检查实际单位。JSON 的 `deer_scale`、`forest_scale` 例如 0.01/1.0/10.0 可调整。
5. `deer_yaw_degrees` 修正朝向：本项目约定模型朝 -Z；反向模型试 180。`deer_offset`、`forest_offset` 是 `[x,y,z]`。
6. 森林如果只是贴图、FBX 材质不完整、模型悬空，需在 Godot 的导入面板/材质检查后另存为合适资源；当前未见原始资产，不能预先保证兼容。
7. 伙伴不用新模型。CompanionDeer 会调用相同 `deer_model`，事件三才显现。

动画：选择 MainDeer 与 CompanionDeer，Inspector 的 `Idle / Walk / Eat / Rest / Alert Animation Name` 填实际名字。可在导入模型的 AnimationPlayer 查看动画列表。没有匹配则试 Idle，没有 AnimationPlayer 则跳过动画，但 AI 和事件继续。实际动画播放采用柔和混合；不依赖 AnimationTree 或插件。

### UI 与明信片

头像四张和明信片三张放默认位置或改 JSON。允许 PNG/JPG/WebP 等 Godot 支持图片。不同名字不用重命名，映射到实际 `res://` 路径即可。

首页图片保持比例；明信片只有 TextureRect 显示原图，没有自动加字。缺图只显示「资源尚未导入」，不会崩溃。

### 视频与声音

视频需要 **Theora 编码的 .ogv**，仅将 .mp4 扩展名改成 .ogv 没有效果。README 已给 FFmpeg 转码命令。当前界面默认视频 16:9；若原视频是其他比例，修改 documentary_player.gd 的 `aspect.ratio` 为实际宽高比。

可选 forest_ambience 存在才创建音频节点，音量 -18 dB，通过 finished 信号循环。`ui_hover`、`postcard_open` 只是 JSON 中预留槽位，本版没有接入播放，不会在明信片解锁时加入奖励声。

## 第六部分：NavigationMesh 初学者教程

### 先运行默认平地导航

Game.tscn 已有 NavigationRegion3D 和一个 36 × 36 米矩形 NavigationMesh。JSON 的 `use_flat_navigation=true` 会以 `navigation_half_extent=18` 和 `ground_height=0` 在运行时更新它。临时森林的树在外围，不挡矩形行走区。这是为了让缺失资产时也能完整演示，不是适配未知森林的最终导航。

### 在真实森林上烘焙

1. 打开 `Game.tscn`。为了让编辑器看见森林，在 **NavigationRegion3D 下**新建名为 `BakeGeometry` 的 Node3D，将森林 GLB 拖进去。调整比例与位移到游戏里的参数。
2. 这是供烘焙读取的副本；在 Inspector 取消 BakeGeometry 的 Visible，避免运行时和 EnvironmentRoot 的森林重复渲染。Visibility 不等于删除 Mesh，默认 NavMesh 几何解析仍读 Mesh；若你的导入节点标志导致不可读，可先显示、Bake 后再隐藏。使用 Mesh 解析，不依赖运行时脚本创建的森林。
3. 选 NavigationRegion3D，点 Navigation Mesh → 新建 NavigationMesh（或 Make Unique 后编辑）。
4. NavigationMesh Geometry → Parsed Geometry Type 选择 **Mesh Instances**。Source Geometry Mode 选择 **Root Node Children**，使它读取下方 BakeGeometry。没有碰撞的纯模型也能烘焙。
5. 调整 Agent Height≈1.5、Radius≈0.4、Max Climb≈0.3、Max Slope≈35 度。单元大小先用默认；很大森林可设置 Baking AABB，仅覆盖 Demo 的可走区，避免昂贵全图烘焙。
6. 点 3D 编辑器上方 **Bake NavigationMesh**。等完成，看蓝色/紫色半透明网格覆盖地面，树、石头等障碍附近应留空。如果只有树冠有网格，说明地面模型或斜坡参数需要调整。
7. 把 `data/assets.json` 的 `use_flat_navigation` 改为 **false**，否则脚本会用默认矩形覆盖你的烘焙结果。
8. 在真正可行走的位置摆放 MainDeer、HomeArea、ExploreArea_A/B、CompanionSpawn；坡地需要按地形调整各节点的 Y，不要都设为 0。非平地模式会保留编辑器的高度。
9. 调整 `navigation_half_extent` 足够覆盖这些节点。本版仍限制目标 X/Z 范围，避免动物走出 Demo；随机点投射到导航网格，最终目标必须位于同一个连通区。
10. 运行 Game，编辑器 Debug → Visible Navigation 查看路线区域。鹿移动应经过地面而非障碍。若需要检查路径，临时将代理 `Debug Enabled=true`；确认后关闭。

代理已挂在两只鹿下，脚本使用 `target_position` 和 `get_next_path_position()`，不是靠玩家推着动物走。体朝向用 `lerp_angle` 缓慢转向。已烘焙地形支持沿路径 Y 变化；动物没有独立物理碰撞，可靠性依赖正确的导航网格。

### 没 Bake 时

导航尚未同步或没有可行走区域，AnimalAgent 使用有限矩形内的直线移动，不崩溃。该回退不避真实树木、石头、陡坡；正式森林演示必须 Bake。若导航有网格但目标不可达，特殊行为 45 秒超时后恢复正常状态并可重试；排查标记点是否同一连通区。

## 第七部分：三个事件搭建和配置

默认位置（米，Y=0 地面）：

| 节点 | 位置 | 用途 |
|---|---|---|
| HomeArea / MainDeer | (0,0,0) | 初始熟悉区域 |
| ObservationRig | (0,2.8,13) | 对着鹿，保持安静即可 |
| ExploreArea_A | (-11,0,-8) | 新区域一 |
| ExploreArea_B | (10,0,-9) | 新区域二 |
| CompanionSpawn | (13,0,-13) | 伙伴从较远处出现 |

HomeArea 是可见的编辑器摆放参考。主角真正的 home_position 初始来自 **MainDeer 自身位置**，修改初始区域时应把这两个节点一起移动。ExploreArea_A/B 和 CompanionSpawn 则由 EventManager 直接读取。

### 第一次见面

EventManager Inspector：`First Meeting Min Time=35`；`Meeting Curiosity Threshold=52`；`Meeting Alertness Threshold=30`。安静观察时好奇逐渐增加、警戒降低；距离小于 3 米会增警觉并减少好奇。

满足时间/安静/好奇/警觉条件后以概率发起 APPROACH_PLAYER，目标在观察者约 5 米外。只在鹿处于该状态、主动走过至少 1 米、抵达 4–7 米安全范围且观察者静止时记录。玩家自己靠过来不算；若双方已太近，不发起见面意图。不要用碰撞 Area 单纯判断距离解锁。

### 初次探索

只在见面已记录后，再等 `Exploration Delay=30`，由鹿随机选择 A 或 B，进入 GO_TO_EXPLORE_AREA。抵达未访问区域时记录；随后把该区域当作新熟悉区。玩家不能控制鹿的目的地。

### 新的伙伴

只在探索已记录后，再等 `Companion Delay=30`，显现 CompanionDeer。两只鹿向中间点靠近，距离小于 3 米连续 `Companion Contact Seconds=3` 才记录。两只鹿随后继续自主生活，没有复杂亲昵动画。

### Debug 演示

选 Game 的 Debug Mode 或 EventManager 的 Debug Mode 开启。事件等待缩短到约 5 秒，见面的好奇门槛调低；内部数值仅此时显示。

- F1：提高好奇、降低警戒并准备主动见面；观察者仍须离鹿足够远。
- F2：准备探索；见面必须已完成。
- F3：准备伙伴出现；探索必须已完成。
- F4：重置所有进度并重新进森林。

快捷键不会直接伪造“任务完成”，仍由实际动物移动和接触触发事件。片段查看时世界暂停，因此快捷键不会跳过当前明信片。

## 第八部分：明信片系统与存档

三个 ID 对应 JSON 的 `postcards`：FIRST_MEETING、FIRST_EXPLORATION、NEW_COMPANION。PostcardData 有 `postcard_id`、`image_path`、`unlocked`。

1. EventManager 验证行为后调用 GameManager 持久记录。
2. SaveManager 写 `user://hidden_wildlife_save.json`，包含三个 `_completed`、三个 `_postcard_unlocked` 和 `documentary_unlocked`。
3. 同时发信号，PostcardManager 将对应资源解锁，通知 Viewer。
4. Viewer 设置黑色 alpha=0.76 遮罩，直接出现原图，`get_tree().paused=true`。
5. Viewer 自身 Process Mode=Always，按钮和 ESC 在暂停状态继续可用。鹿、观察输入、EventManager 为普通继承模式，停止处理。
6. Continue 恢复暂停前状态。若从收藏进入 Viewer，Viewer 不拥有世界暂停，因此关闭后不会意外让收藏后面的世界继续走。
7. 重新进森林时已完成的事件不会自动弹出，收藏仍可重看。
8. 集齐三张仅启用 HUD 的「观看生命纪录片」，绝不自动切片。玩家自己点击。

存档使用临时文件写入后原子替换。损坏 JSON 保留 `.damaged` 副本并以空白进度继续；不会把无效字符串当成 true。事件顺序和纪录片解锁由已完成事件推导。没有每天日志、数据库或云端存档。

## 第九部分：从空项目到可运行的操作步骤

### 推荐：导入已搭建项目

Step 1：解压项目到一个完整文件夹。

Step 2：Godot 4.3+ 项目管理器选择 Import，选 `project.godot`。

Step 3：等字体和测试视频导入完成，无需安装其他依赖。

Step 4：按 F5，进入档案主页。选择毛冠鹿进入观察。

Step 5：静止观察，三次片段各点继续，再主动打开纪录片。资源未导入时看到明确缺失提示。

Step 6：按 README 导入你的 ZIP 或手动复制媒体。重开 Godot 等 Import。

Step 7：在 `data/assets.json` 修改实际路径、比例、方向和位移。

Step 8：用本说明的导航教程在真实森林 Bake，摆正初始鹿与所有区域标记。

Step 9：先启用 Debug Mode 核验三个事件、动画、图片、视频，再关闭 Debug Mode 演示自然节奏。

Step 10：Godot Project → Export，安装与你编辑器版本一致的官方 Export Templates，添加 Windows/Linux/macOS 对应预设后导出。当前交付为**源码项目**，没有宣称已生成桌面可执行文件或测试导出包。

### 若必须先创建空项目

Step 1：在 Godot 建立空项目，选择 Compatibility renderer。

Step 2：关闭编辑器，将本项目 `scenes/`、`scripts/`、`data/`、`assets/`、`tools/`、`tests/`、`docs/` 复制到空项目目录。

Step 3：使用随附 `project.godot` 替换空项目初始配置，或照第四部分手动设置 Autoload、Input Map、Main Scene 和显示尺寸。

Step 4：重新打开，按上面的 Step 3–10 继续。本项目 `.tscn` 和完整 `.gd` 已给出，无需手动重建每个节点。
